From Overlay to Agent
AI workflows for landscape and design

Who’s in the room?

Four quick questions, to know the room.

  • Hands up if you use GIS in your work or studies.
  • Hands up if you use Grasshopper or any scripting.
  • Hands up if you have used a chat assistant for work or school.
  • Hands up if you have used an agent that edits files for you.

By the end of this session, you will be able to

  • Trace computation in landscape architecture from McHarg’s overlay through GIS, CAD and parametric modeling, and place AI agents in that lineage.
  • Explain how an agent differs from a chat assistant, and how MCP connects an agent to software you already use.
  • Apply folder structure and a written context file to control what an agent knows across working sessions.
  • Evaluate which tasks in your own work can be delegated to an agent, weighing verification, confidentiality, cost and time.

Tools accumulate

  • None of these replaced another. They piled up.
  • Almost none were built for landscape: borrowed from defense, car factories, highways, the movies, games.
  • The right edge is a question. Agentic AI is not a new bar; it washes across all of them.

“Scores communicate but do not control.”

  • Halprin’s RSVP Cycles: Resources, Scores, Valuaction, Performance.
  • A score sets conditions; the performance is not the score.
  • Directing an agent is writing a score, then reading the performance back.

MCP is the key to the door.

Several companies make coding agents

  • Claude Code (Anthropic), Codex (OpenAI), Cursor (Anysphere), Gemini CLI (Google), and others. All of them work inside a folder on your computer.
  • They share open standards: MCP to connect software, AGENTS.md for a project’s instructions.
  • The examples today use one of them. Naming them is not an endorsement.

The project’s standards manual

  • An assistant who forgets everything overnight. AGENTS.md (some tools read CLAUDE.md) is the manual it reads each morning.
  • You talk; the agent writes it. “Add that to AGENTS.md.”
  • Your job: judge what belongs, what it cannot learn from the files.
  • Every line loads every session. Ask it to audit and shorten the file.

Before an agent touches project files

What would your conditions be?

  • Where does the data go? Which files leave the machine, to whom, under what terms.
  • Who checks? Which outputs a person must review before they go out.
  • Who owns the context files? Someone keeps the manual current, or it drifts.
  • What does it cost? A subscription, and someone’s hours to set up and keep it current.

From Overlay to Agent

Talk · 2026

A talk for landscape architects, designers and students on AI agents: tools that work inside a project folder, read and edit its files, and connect to software you already use. It starts from a claim about the profession. Landscape architects have always done computation, first on layers of mylar and later in GIS, CAD and Grasshopper, and almost none of those tools were built for the discipline. Agents are the first tools a designer can reshape around their own work by describing what they want.

The talk traces that lineage from Eliot and McHarg through SYMAP, AutoCAD and parametric modeling; explains how an agent differs from a chat assistant and how the Model Context Protocol connects it to programs like Rhino; and shows how folder structure and a short context file, written and maintained by the agent itself, carry a project across working sessions. It closes Part 3 with the workflow behind this website, from setup to the daily routine. A discussion follows on what designers would hand over, what they would keep, and the conditions an agent must meet before it touches client or confidential files. The last part points to two hands-on guides, for anyone who wants to try it in the room or later.

Two step-by-step guides continue the hands-on work: an agent inside Rhino and folder context and a website on GitHub.
