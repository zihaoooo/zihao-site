This week you build and publish a portfolio site. The site is the outcome. The skill is context engineering: deciding what a coding agent reads, in what order, and where that information lives so it lasts beyond a single conversation.
In WF06 you moved the slope code out of the .gh file and into a .py that sat in a folder where Claude could read it. This week the whole project works that way. You set up the folder and write down what matters in it. Claude reads the folder at the start of every session and builds from there.
Part 1 The Folder Is the Context
01 What Claude Knows Read first
Every Claude Code session starts knowing nothing about your project. All it has to work with is its context window: its own instructions, any CLAUDE.md files, the files it has opened, and the conversation so far. Anything outside that window simply isn't there for it.
The window has a limit. When a session runs long, Claude Code summarizes the older turns to make room. Details you only said once in conversation are the first to blur. When you close the session, the conversation is gone. The files stay.
Context engineering is managing that window on purpose: choosing what goes in, what stays out, and what gets written down so the next session starts from it.
  • The conversation is short-term memory. Use it to steer the work you're doing right now.
  • The folder is long-term memory. Decisions you want to keep go into files.
  • CLAUDE.md is the note Claude reads first. It says what the project is and where everything lives.
A simple test: if you'd have to say something again next session, write it into a file.
02 Set Up SETUP
You already have Claude Desktop from WF06. Add two things:
  • GitHub account: sign up free at github.com. This is where your site lives.
  • Git for Windows: download from git-scm.com, click Next through the installer, and leave all defaults. On a Mac, Claude will install Git for you the first time it needs it.
03 Build the Folder
In File Explorer, make a folder called my-portfolio. Inside it, make _source and put your material there: a short about text, your resume, and three to six project images at full size. Leave the rest empty. Claude builds it.
my-portfolio\
│
├─ CLAUDE.md          read at the start of every session
├─ .gitignore         keeps _source\ off GitHub (Step 09)
│
├─ _source\           YOUR MATERIAL — you put it here
│   ├─ about.txt
│   ├─ resume.pdf
│   └─ images\        full-size exports, any size
│
├─ index.html         THE SITE — Claude builds these
├─ resume.html
├─ assets\img\        web-sized copies of your images
└─ projects\
    ├─ CLAUDE.md      read when Claude works in projects\
    └─ riverside.html
Claude explores a folder by listing names before it opens anything. Clear names tell it where to look, and every file it doesn't have to open leaves more room in the window for your actual work. riverside.html tells Claude more than page3_final_v2.html.
Open Claude Desktop → Code tab → select my-portfolio. From now on, that folder is Claude's world.
04 Write CLAUDE.md
CLAUDE.md is a plain text file at the root of the folder. Claude Code loads it automatically whenever a session opens this folder. Have Claude draft it from your material:
Read everything in _source. Then write a CLAUDE.md at the root of this folder: who I am, what the site is for, which pages it has, what each folder holds, and the rules for web images. Keep it under 40 lines. Show it to me before you build anything.
Open it and edit it yourself. It's your file, and a short one. Something like:
# my-portfolio

Portfolio site for Jane Doe, MLA student at CCNY.
Plain HTML and CSS, published on GitHub Pages.

## Folders
- _source/     my raw material. Read it; keep it off the site.
- assets/img/  web copies, built from _source/images/
- projects/    one page per project. See projects/CLAUDE.md.

## Pages
index.html (about) · projects/ · resume.html

## Images
Feature: 1600–2000 px long edge, under 500 KB.
Gallery: 1000–1200 px, under 300 KB.
JPG for photos and renders; PNG only for transparency.

## Style decisions
Serif headings, gray on white, generous margins.
  • Put in it what Claude can't work out by reading the files: purpose, folder map, rules, decisions you've made.
  • Keep it short. It loads into every session, so every line costs context every time. Put long reference material in its own file and have CLAUDE.md point to it.
  • Each rule lives in one place. The image sizes are written here and nowhere else. Step 07 comes back to this.
Part 2 Build, and Keep the Memory in Files
05 Build the First Version CODE
Following CLAUDE.md, resize my images into assets/img, then build the about page, one project page, and the resume page. Open a preview when it's ready.
The preview opens in a pane inside the app. Iterate in plain language: "make the header bigger," "use a darker background." Claude edits the real files in your folder.
When you settle something you want to keep, send it to the file:
Add that to the style decisions in CLAUDE.md.
The preview only runs while the app is open. Nothing is online yet. That comes in Part 3.
06 One CLAUDE.md per Folder
The root CLAUDE.md loads when the session starts. A CLAUDE.md inside a subfolder loads only when Claude starts working with files in that folder. That lets the root file stay short: it points, and the details sit next to the files they govern.
Write projects/CLAUDE.md describing the template every project page follows — sections, image sizes, caption style. Then use it to add a second project from _source.
Claude never needs the project template while it's editing your resume, so the template stays out of the window until Claude needs it.
07 Revise Against Three Rules
Your CLAUDE.md files have grown as you built. Before you test them, check them against three habits from software practice.
DRY — Don't Repeat Yourself. Write each fact once. Say you put the image sizes in the root CLAUDE.md and again in projects/CLAUDE.md. Later you change one copy and forget the other. Claude now has two answers, and it has to guess which one you meant. Write the rule once and point to it from everywhere else:
projects/CLAUDE.md
  Image sizes: see the root CLAUDE.md.
SSOT — Single Source of Truth. For each thing in the project, decide which file is the original and which files are built from it. Your resume PDF in _source is the original, and resume.html is built from it. To update your resume, edit the PDF and ask Claude to rebuild the page. If you edit the HTML directly, the two drift apart and nothing tells you which one is current. State the originals in CLAUDE.md so Claude knows which file to change.
Don't think of an elephant. The linguist George Lakoff made the point that naming something puts it in the listener's mind, even when you name it to rule it out. Language models behave the same way: "don't use Comic Sans" brings Comic Sans into the context. Write the thing you want instead.
✗  Don't use Comic Sans. Never center body text.
✓  Serif for headings, sans for body. Body text left-aligned.
Keep the negative wording only for hard limits that have no positive form. The rewrite usually turns out clearer for you as well as for Claude.
Then have Claude audit the files, and approve each fix yourself:
Check every CLAUDE.md in this folder against three rules: each fact written once, the original file named for anything that gets built, and every rule phrased as what to do. List what breaks a rule and propose a fix for each. Change nothing until I approve.
08 The Cold-Start Test
Close the session and start a new one in the same folder. Claude now knows only what the folder tells it. Ask:
What is this project, how is it organized, and what's left to do?
If the answer is right, your files are carrying the project. If Claude gets something wrong or misses a decision, fix CLAUDE.md, then start another session and ask again. Leave the conversation out of it: the next session won't see anything you explain there.
When the answer is right, take a screenshot of it. That goes in your submission.
Use this whenever a long session starts forgetting things you settled an hour ago. Save the decisions to CLAUDE.md, open a fresh session, and keep going. Starting over costs you nothing, because the folder carries the project.
Part 3 Publish
09 Publish to GitHub GitHub
Create an empty repository on GitHub. Click + → New repository, name it my-portfolio, leave all defaults, and click Create repository. Leave it empty. Your files come from your folder.
Push from Claude Code. Copy the repo URL and ask:
Add a .gitignore that keeps _source out, then commit everything else and push to https://github.com/yourname/my-portfolio.git
Enable GitHub Pages. In your repo on github.com: Settings → Pages → deploy from the main branch, root folder.
10 Your Site Is Live
Your site is public at yourname.github.io/my-portfolio. It's the same files as your preview, hosted online.
To update: open a session in the folder, make the change, and ask Claude to commit and push. The live site refreshes within a minute or two. CLAUDE.md goes up with the site, so the project also works on any other computer you clone it to.
Where Claude Looks
CLAUDE.md files stack. Claude Code reads every one on the path from your user folder down to the folder you opened, then picks up deeper ones as it works.
C:\Users\you\.claude\CLAUDE.md     you, in every project
Documents\CLAUDE.md                any folder above, if present
my-portfolio\CLAUDE.md             this project
        ── all loaded when the session starts ──

my-portfolio\projects\CLAUDE.md    loaded when Claude opens
                                   a file in projects\
The top one is for things true everywhere — your name, the language you want replies in, how you like to work. A folder that holds several projects can carry one CLAUDE.md they all share. Each level says only what applies at that level.
This is how larger projects stay manageable. The top files are short and point downward. Claude follows the pointers the way you would follow a drawing index to the one sheet you need.
What Is Git?
Git keeps a history of every saved version of your files. It works like version history in InDesign or Photoshop, but for the whole project folder, and you choose when each snapshot is taken. You keep one folder instead of site_final_v2_REALLY_final, and Git remembers each saved state so you can always go back.
Three names that get mixed up:
  • Git tracks the snapshots on your own computer.
  • GitHub stores a copy online, so it's backed up and shareable.
  • GitHub Pages serves the files in a GitHub repo as a free public website.
Claude Code runs Git for you. The idea is what matters: saves you take on purpose and can return to, backed up online and served as a site.
