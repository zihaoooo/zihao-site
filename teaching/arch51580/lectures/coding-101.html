A computer does not understand your project. It holds a list of steps and a finger on its place in the list.

Everything that looks like judgment is built on top of that, by doing it a few billion times a second.

Three operations, forever

  • Fetch — read what is in a labeled box.
  • Do — one operation: add, compare, join.
  • Store and step — put the answer somewhere, move down one line.
  • So: it never guesses. An ambiguous instruction does not come back as a question. It comes back as a confident wrong answer.
  • And: it never tires. The thousandth repetition is as exact as the first.

Three kinds of instruction

A recipeA Halprin scoreA script
Who runs itA cookA group of peopleA machine
Ambiguity isTolerated — “season to taste”The point — the score invites variationFatal — it stops, or does the wrong thing exactly
Runs againRoughly the sameDeliberately differentIdentically, every time
Leaves behindA mealAn event, and a record of itFiles, and a readable trace of how they were made
The score and the script sit at opposite ends of one tradition — we come back to this in Cybernetics and Design.

A script is a process, drawn.

A plan abstracts a place so someone else can build it. A script abstracts a procedure so a machine can run it. Same move, different subject.

Before you run it

                  
    
                    
  • Which files does it touch? Find the Move 5 lines. There are usually two or three, and they are the whole risk.
    • 
                    
  • Does it write beside, or over? A new filename is safe. The same filename replaces your original, and there is no undo.
    • 
                    
  • Is it looping over the right set? *.jpg and * are a very different afternoon.
    • 
                    
  • Can it tell me first? Ask for the printed version — print what it would do, change nothing — and read that list before letting it act.
    • 
                  

                  
    
                    
  • Then: run it on five files, not five hundred.
    •
