Nobody is asked to write a script from a blank file today. You will read four of them, predict what two of them do, break one on purpose, and then have the agent write the fifth from a paragraph you wrote. The order matters: predict before you run. A prediction you got wrong teaches you where your model of the machine is off, and running the thing first robs you of that.
Work in the project folder you set up in the first session. Keep a scratch copy of five images beside it — never point a first run at originals.
01 Check the Install
Open a terminal in your project folder and confirm the three things this course runs on. Each should answer with a version number. If one does not, fix it now — the rest of the session depends on all three.
Terminal 
python --version        # or: py --version  (Windows)
git --version
claude --version        # the agent, if you installed the CLI
Then install the one library this session needs. Pillow reads and writes images; version 12 or later is what writes .avif.
Terminal 
python -m pip install --upgrade pillow
python -c "import PIL; print(PIL.__version__)"     # want 12.0 or higher
  • Windows: py is the launcher that finds your Python install even when python does not. Use py -m pip install … there.
  • Make a scratch folder now: copy five of your images into scratch/. Everything today runs there first.
02 Predict, Then Run
Here is the loop from the lecture, with one line added. Read it, then write your prediction on paper before typing anything.
predict.py 
sheets = ["plan", "section", "axon", "detail"]
count = 0

for s in sheets:
    count = count + 1
    if count % 2 == 0:
        print(count, s, "(even)")
    else:
        print(count, s)

print("total:", count)
Write this down before you run it How many lines does it print? Which of them carry the word even? What is the last line? — % is the remainder after division, so count % 2 == 0 is true when count is even.
Now save it and run it. Compare, line by line, with what you wrote. If they differ, find the line where your reading and the machine's parted company — that single line is the most useful thing you will learn today.
Terminal 
python predict.py
03 Change One Number
Change % 2 to % 3, predict again, run again. Then add a fifth sheet to the list and predict the last line before running. You are building the habit the whole course rests on: a small change, a prediction, a check.
  • Keep each run's output. Three runs beside each other show the rule more clearly than any explanation of it.
04 Break It on Purpose
Make these three mistakes one at a time, run after each, and write down what the traceback told you — which file, which line, what it expected. Read from the bottom up. Put each line back before making the next mistake.
  • Delete the colon at the end of the for line. The machine stops before running anything at all.
  • Misspell count on one line only. Notice that it runs until it reaches that line, then stops.
  • Move count = 0 inside the loop, as its first indented line. The script runs to the end, reports no error, and is wrong. This is the dangerous kind.
The point of the third one The first two stop the script and tell you where. The third finishes, prints four tidy lines and a total of 1, and says nothing is wrong. That difference is why reading the output matters more than reading the errors.
05 Write the Spec in English
Now your own job. In one paragraph, describe what should happen to your folder of images. Be as exact as a drawing note: name the input folder, the output folder, the filename pattern, the size limit, the format. Vagueness here is what produces a wrong script later.
Shape of a usable spec 
Read every .jpg and .png in scratch/, longest edge over 1920px.
Shrink those to 1920px on the longest edge, keep the proportions.
Write them as .avif at quality 65 into scratch/web/, which the
script should create if it is missing. Name each output after the
input file, lowercase, spaces turned into hyphens. Leave the
originals untouched. Print one line per file saying what it wrote.
  • Six sentences is plenty. Each one removes a decision the agent would otherwise make for you.
  • “Leave the originals untouched” and “print one line per file” are the two sentences that make the result checkable. Always include their equivalents.
06 Hand It to the Agent
Give the agent your paragraph and ask for a single Python file. Add one instruction to the end: ask it to print what it would do and change nothing, so you get a dry run first.
What you type to the agent 
Write one Python file, encode.py, that does this:

[your paragraph from step 05]

Add a --dry-run flag that prints every file it would write
without writing anything. Use Pillow. No other dependencies.
  • Resist reading the explanation it writes around the code. Read the code. That is the deliverable; the prose is packaging.
07 The Four Questions
Before running it, answer all four in writing. Point at the line number that answers each. If you cannot find the line, you have not read the script yet.
  • Which files does it touch? Find every line that opens, saves, moves or deletes. Usually two or three.
  • Does it write beside, or over? Compare the output path to the input path. If they can ever be the same string, stop and fix it.
  • Is it looping over the right set? Check the pattern. *.jpg misses .JPG on some systems; * catches your PDFs.
  • Can it tell me first? Confirm the dry-run path really writes nothing — read it, do not take the flag's name on trust.
08 Dry Run, Then Five Files
Run the dry version and read the list. Does it name the files you expected, and only those? Then run it for real on scratch/ — five files, not five hundred. Open two of the outputs and look at them. A script that reports success and produces grey rectangles has reported success.
Terminal 
python encode.py --dry-run     # read this list before going further
python encode.py               # now, on the five scratch files
  • Check a file size as well as the picture. An .avif that is larger than its .jpg means a setting is wrong.
09 Note What You Had to Correct
Write two or three lines under the script: what the agent got wrong, and whether it was wrong because your spec was vague or because it guessed. That distinction is the thing to keep. Across a semester, the first kind teaches you to write; the second teaches you where to look.
Carry this forward Commit the script, the spec paragraph and the note together. By the midterm, this folder of notes is the most accurate description you own of how you actually work with an agent — and it is where your Part II project will come from.
